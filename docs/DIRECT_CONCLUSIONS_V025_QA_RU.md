# «Тише» v0.25.0 — прямые выводы по всем тестам

## Задача от пользователя

При любом полностью завершённом тесте нельзя показывать только «паутинку» и размытое описание последних дней. Первым экраном показывается короткий конкретный вывод: **какие трудности человек сам отметил**, либо что он **не отметил частых проблем в этих вопросах**, затем пояснение и понятное следующее действие.

### Правила

1. **Не считать авторский тест диагнозом.** Для 40/150/300/500 это не клинические инструменты. Допустимо: «По вашим ответам у вас часто возникают трудности с раздражением и гневом». Недопустимо: «У вас диагностировано расстройство гнева», «Вы тревожная личность», «Вам необходимо лечение».
2. Шесть первых направлений: в 3 и более из 4 ответов варианты 3–4 дают прямой вывод **«часто возникают трудности»**; 2 высоких — **«заметные сложности»**; 1 высокий/2 («иногда») — **«отдельные сложности»**. Это прозрачное правило интерфейсного резюме, **не медицинские пороги**.
3. Если ни в одном направлении нет частых отметок, честный результат — «По тесту вы не отметили частых трудностей в шести основных темах»; **не** «Вы полностью здоровы».
4. Ответы, пропущенные или вне диапазона, не подставляются и не влияют на расчёт. При неполном тесте слова «предварительный итог»; отсутствие ответов — «тест ещё не пройден».
5. Для 150/300/500 дополнительно показываются **реально выбранные утверждения** из других блоков; противоположно направленные формулировки нельзя объединять в индекс проблем. IPIP показывает только направление согласия при полном наборе, с обратным кодированием; не выдаёт диагноз или личностный тип.
6. Авторские отдельные опросы дают прямое описание выраженности отмеченных утверждений; интересы — **предпочтения**, ресурсы — **возможные трудности с отдыхом**, а не фиктивная общая «проблемность».
7. PHQ-4 — отдельный добровольный скрининг, требует 4 ответа с диапазоном 0–3; вывод содержит известную описательную категорию по сумме 0–12, но **не** диагноз.
8. В каждом полностью отвеченном тесте: короткий вывод, причина, реальные отмеченные пункты (если были), один следующий шаг. Всё офлайн. Не менять ID вопросов, Keystore alias, формат JSON, старые ответы.

## QA

- 40 вопросов: 0/4 в шести темах → без ложной проблемы; 3–4 высоких по гневу → конкретное указание на трудности с гневом.
- 150/300/500: итог плюс контекст, подходящие IPIP-разделы, без фиктивной клинической тяжести; часть ответов → предварительный итог.
- Каждый из отдельных опросов: есть непустой содержательный вывод, причина и действие; PHQ-4 и IPIP остаются особыми случаями.
- Проверить на телефоне: после последнего вопроса виден итог, его удобно прокрутить, работает Back, большие шрифты не обрезаются; пересчитанные результаты читают прежние сохранённые ответы.
- CI-команды: `gradle --no-daemon :app:assembleDebug :app:testDebugUnitTest :app:lintDebug` и `aapt dump badging`, с документированным результатом GitHub Actions.
- Статус до ручного QA: **реализовано в QA-ветке, Android device UI ещё не проверено**.
